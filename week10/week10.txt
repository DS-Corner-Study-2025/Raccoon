모킹(mocking): 가짜 객체, 가짜 함수를 넣는 행위
모킹 방식은 외부 환경(DB, 세션)에 의존하지 않고 미들웨어 내부의 분기 로직만 독립적으로 검증할 수 있게 해줌

미들웨어를 유닛 테스트하기 위해서는 라우터 핸들러 내부에 익명 함수로 작성하는 대신, 별도의 파일로 로직을 분리해야 한다. 
그래야 테스트 코드에서 해당 함수를 직접 require하여 독립적으로 검증할 수 있기 때문이다.

1. Node.js 환경에서 테스트 자동화를 위해 설치하는 프레임워크는 jest이며, 
테스트용 파일은 파일명과 확장자 사이에 test 또는 spec을 넣어 구분한다.

2. 유닛 테스트를 위해 실제 객체나 함수 대신 가짜를 넣어 독립적인 테스트 환경을 만드는 기법을 모킹이라 하며, 
이를 위해 jest.fn(Mocking) 메서드를 사용한다.

3. 미들웨어 테스트 시 res.status(403).send(res)와 같은 메서드 체이닝을 재현하려면, 
res.status 가짜 함수가 실행된 후 자기 자신을 반환하도록 설정해야 한다.

4. 코드의 테스트 비중을 확인하는 npm run coverage 실행 결과 중, i
f문이나 switch문 등의 조건문이 얼마나 실행되었는지를 나타내는 항목은 % Branch이다.

5. 실제 서버의 라우터와 미들웨어가 유기적으로 작동하는지 확인하는 통합 테스트를 위해 사용하는 라이브러리는 supertest이다.
