  - 의존 관계


<Package.js>
: 설치한 패키지의 버전을 관리하는 파일
  - 패키지를 동일한 버전으로 설치하지 않을 시, 문제 발생 가능성 O
: 따라서 노드 프로젝트를 시작하기 전에는 폴더 내부에 무조건 package.js를 만들고 시작해야 함

1.) package.js 만드는 법
$npm init
...
package name : (폴더명) [프로젝트 이름 입력]
version : (1.0.0) [프로젝트 버전 입력]
description : [프로젝트 설며어 입력]
entry point : index.js
test command : [코드를 테스트할 때 입력할 명령어]
git repository : [코드를 저장해둔 깃 저장소 주소]
keywords : [npm 공식 홈페이지에서 패키지를 쉽게 찾을 수 있게 함]
author : [저자 이름]
license : (ISC)
...
Is this ok? (yes) yes

=> 완료되면 폴더에 위의 내용이 담긴 파일(package.json) 생성됨

2.) 패키지 설치
$npm install [패키지 이름] [패키지 이름] ...
$npm install --save -dev [패키지 이름] [패키지 이름] ...
  - 개발자용 패키지

3.) 패키지 수정
$npm i patch-package  
(node-modules 내부의 원하는 패키지 수정하기)
$npx patch-package [수정한 패키지 이름]

<익스프레스>
: 대표적인 웹 서버 프레임워크
: $npm install express 를 통해 설치

1) 익스프레스 프로젝트 과정
- 익스프레스 프로젝트를 실행할 폴더 생성
- package.json 생성 (항상 먼저 만들어줘야 함)
- package.json 폴더 안에서...
  > scripts 부분에 start 속성 넣기 (반드시)
  > "start" : "nodemon.app"
    >> app.js를 nodemon으로 실행한다는 뜻
    >> 서버 코드를 수정하면 nodemon이 자동으로 서버를 재시작시켜 줌 
       (콘솔에 rs 입력하여 수동으로 재시작시킬 수도 있음)
- app.js 폴더 안에서...
  > const app = express();
    >> express 모듈을 실행해 app 변수에 할당
  > app.set('port', 포트)
    >> 서버가 실행될 포트 설정
  > app.get(주소, 라우터)
    >> 주소에 대한 GET 요청이 올 때, 어떤 동작을 할지 적음
  > app.listen(app.get('port'))
    >> 포트를 연결하고 서버 실행


<미들웨어>
: 익스프레스의 핵심 기능
: 요청과 응답 중간에 위치
: 요청과 응답을 조작해 기능을 추가하기도 하고, 나쁜 요청을 걸러내기도 함
: app.use와 함께 사용됨
- app.use(미들웨어) 형식
  > app.use(미들웨어) : 모든 요청에서 미들웨어 사용
  > app.use('/abc', 미들웨어) : abc로 시작하는 요청에서 미들웨어 실행
  > app.post('/abc', 미들웨어) : abc로 시작하는 POST 요청에서 미들웨어 실행

1) 미들웨어 종류
- morgan
  > 요청과 응답에 대한 정보를 콘솔에 기록
- static
  > 정적인 파일들을 제공
- body-parser
  > 요청의 본문에 있는 데이터를 해석해서 req.body 객체로 만듦
- cookie-parser
  > 요청에 동봉된 쿠키를 해석해 req.cookies 객체로 만듦
- express-session
  > 세션 관리용, 로그인 등의 이유로 세션을 구현하거나 특정 사용자를 위한 데이터를 임시적으로 저장해둘 때 유용
- multer
  > 이미지, 동영상을 비롯한 여러 가지 파일을 멀티파트 형식으로 업로드할 때 사용

2) 미들웨어 특성
- 여러 개의 미들웨어를 동시에 장착할 수 있음
- 다음 미들웨어로 넘어가려면 next 함수를 호출해야 함
  > 만약 next도 호출하지 않고, 응답도 보내지 않으면 클라이언트는 응답을 받지 못해 하염없이 기다리게 됨
- 미들웨어 장착 순서에 따라 어떤 미들웨어는 실행되지 않을 수 있음


<템플릿 엔진>
: 자바스크립트를 사용해서 HTML을 렌더링할 수 있게 함

1) Pug(퍼그)
- $npm i pug 로 설치
- 기존 HTML과 달리 (<>)와 같이 닫는 태그가 없음
  > Only 탭 또는 스페이스로 태그의 부모 자식 관계를 규명
    >> <!DOCTYPE html> -> doctype html
    >> <div id="login-button"></div> -> #login-button (id = #, class=.)
    >> <p>Welcome> -> p Welcome
    >> <stlye> </stlye> -> stlye. (script도 마찬가지로 . 붙이기)
- res.render(템플릿, 변수 객체)
  > HTML에서도 변수 사용 가능
- each ~
  > 반복문 사용 가능 (each 대신 for 써도 됨)
- if, else if, else
  > 조건문 사용 가능
- include
  > 다른 퍼그나 HTML 파일 넣기 가능
- extends와 block
  > 레이아웃을 정할 수 있으며, 공통되는 레이아웃 부분을 따로 관리할 수 있음

2) 넌적스
- $npm i nunjucks 로 설치
- 변수를 {{}}로 감쌈
  > 내부에 변수를 사용할 수도 있음
  > 변수를 선언할 때에는 {% set 변수 = '값' %} 사용
- {% 반복문 %}
  > loop.index 를 통해 반복문 안에서 인덱스 사용 가능
- {%if 변수%}, {%elif 변수%}, {%else 변수%}, {%endif 변수%} 
  > 조건문 사용 가능
- include
  > 다른 HMTL 파일 넣기 가능
- extends와 block
  > 레이아웃을 정할 수 있으며, 공통되는 레이아웃 부분을 따로 관리할 수 있음
