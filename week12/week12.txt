pm2
pm2는 원활한 서버 운영을 위한 패키지

  - 가장 큰 기능은 서버가 에러로 인해 꺼졌을 때 서버를 다시 켜줌

  - 멀티 프로세싱을 지원해 노드 프로세스 개수를 한 개 이상으로 늘릴 수 있다

  - 그러나 멀티 스레딩이 아니므로 서버의 메모리 같은 자원을 공유하지는 못함

    > 세션을 공유할 수 있게 해주기 위해 멤케시드(Memcached)나 레디스(Redis) 같은 서비스를 이용

 

  - pm2 설치 : npm i pm2

  - pm2 사용 : npm start 스크립트 수정 

    > start 부분을 "cross-env NODE_ENV=prodution PORT=80 pm2 start server.js" 로

    > 기존 nodemon 대신 pm2 사용하게 됨

  - 백그라운드에서 돌고 있는 노드 프로세스 확인 : npx pm2 list

  - 현재 프로세스 모니터링 : npx pm2 monit

  - pm2 프로세스 종료 : npx pm2 kill

  - 서버 재시작 : npx pm2 reload all





winston
실제 서버를 운영할 때 console.log와 console.error를 대체하기 위한 모듈



console 객체의 메서드들은 언제 호출되었는지 파악하기 힘듦 + 서버가 종료되는 순간 로그들도 사라져버림

  > 이와 같은 상황을 방지하기 위해 로그를 파일이나 다른 데이터 베이스에 저장하는 winston을 사용



npm i winston 설치

//logger.js
const { createLogger, format, transports } = require('winston');

const logger = createLogger({
  level: 'info',
  format: format.json(),
  transports: [
    new transports.File({ filename: 'combined.log' }),
    new transports.File({ filename: 'error.log', level: 'error' }),
  ],
});

if (process.env.NODE_ENV !== 'production') {
  logger.add(new transports.Console({ format: format.simple() }));
}

module.exports = logger;
- winston 패키지의 createLogger 메서드로 logger를 만듦

- 인수 logger에 대한 설정으로 level, format, transports 등이 있음

- logger 객체를 만들어 다른 파일에 사용할 수 있음 (info, warn, error 등의 메서드)

connect-redis
멀티 프로세스 간 세션 공유를 위해 레디스와 익스프레스를 연결해주는 패키지

기존에는 서버가 종료되어 메모리가 날아가면 접속자들의 로그인이 모두 풀려버림

  > 이를 해결하기 위해 세션 아이디와 실제 사용자 정보를 데이터베이스에 저장

  > npm i redis connect-redis  (레디스를 사용하려면 connect-redis 패키지뿐만 아니라 레디스 데이터베이스를 설치해야 함)

  > 세션 정보가 메모리 대신 레디스에 저장되어 로그인 후 서버를 껐다 켜도 로그인이 유지





깃과 깃허브 사용하기
깃(Git)

  - 분산형 버전 관리 시스템

  - 깃은 하나의 컴퓨터에서 코드를 관리하는 데 사용

깃허브(GitHub)

  - 깃으로부터 업로드한 소스 코드를 서버에 저장할 수 있는 원격 저장소

  - 깃허브에 소스 코드를 업로드하면 여러 사람이 코드를 공통으로 관리할 수 있음



1. 깃 설치하기
- 깃을 설치한 다음 제대로 설치되었는지 확인하기 위해 콘솔에 git --version 로 깃 버전을 확인

//.gitignore
node_modules
uploads
*.log
coverage


2. 깃허브 사용하기

- 회원가입, 로그인 후 리포지터리를 생성

> 소스 코드를 깃에 추가하기 위해 git init

> git add . (모든 파일을 추가하겠다는 의미)

> git config --global user.email " "

> git config --global user.name " "

> git commit -m " " 

> git push origin master (코드를 깃허브에 업로드)
